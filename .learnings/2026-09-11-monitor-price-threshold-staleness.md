# Monitor 触发条件含行情阈值时系统不会自动触发 — 需行情数据比对

**日期**: 2026-09-11
**场景**: 用户问「监控触发下这些事件已经发生了吗」，人工核对发现「伊拉克民兵参战→油价金价双飙」monitor 的 3 个触发条件（民兵攻击美军基地 ✅ 3月起291次 / 布伦特>100 ✅ 现价108.15 / XAUUSD>4100 ✅ 4334）已全部满足，但 monitor 仍挂 active 状态。

**根因**: monitor 触发条件混合两类判定——新闻事实型（民兵是否参战）+ 行情阈值型（布伦特>X、XAU>Y）。EarlyWarningEngine.check_stale_events 的重验机制靠新闻搜索，捕捉不到「行情阈值静默穿越」（油价从 95 → 108 爬升一周+13%，无单一新闻事件对应）。金价维度只看自家 XAU/SGE 数据，不盯布伦特。

**影响**: 18 个 active monitor 中多个含行情阈值（「油价持续>80美元」「XAUUSD>4200」「积存金破920」等），都存在同类滞后风险——条件已满足但系统不报警，直到人工发现。

**处理**: 人工核对后 close_monitor(new_status="triggered") + 结论归档。重要：触发条件满足 ≠ 因果假设成立——该 monitor 的「金价双飙」假设失效（金价被 Fed 加息预期压制下行），归档时必须记录假设哪部分失效，否则后续回测会误判该 monitor 「预测正确」。

**改进方向（未实施）**: 监控扫描（adaptive_gold_monitor 或 scan）对含行情阈值的 active monitor 增加行情比对步骤——正则提取触发条件里的「布伦特>X / XAUUSD>Y / 积存金>Z」阈值，与当日行情自动比对，满足即提示人工确认触发。
