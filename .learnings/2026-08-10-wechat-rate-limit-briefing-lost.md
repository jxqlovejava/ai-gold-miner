# Learning: 微信限流窗口致盘前简报丢失 — 诊断与错峰

Date: 2026-08-10
Trigger: 用户问"为什么我微信端没有动静"（金价分析日后未收到盘前简报）

## 诊断路径（可复用）

1. 先看本地监控日志确认监控活着（`logs/adaptive_monitor.log` 尾部时间戳）
2. `hermes cron list` 看各任务 Last run + `⚠ Delivery failed` 标记 — 投递失败在此现形
3. `~/.hermes/logs/errors.log` grep 当日 `rate limited` 时间分布 → 限流窗口
4. `gateway.log` grep inbound/Sending → 验证通道本身是否存活（当日双向消息正常=通道没死，是窗口性限流）

## 根因

- 多项目共用同一微信号 iLink 通道：白泽( ai-stock-hunter )`*/2 9-14` 每 2 分钟 + 黄金任务 9:21/9:31/9:32 撞车 → 9:19-9:34 窗口 33 条限流错误 → 盘前简报 ret=-2 被丢弃
- hermes cron **无 retry 选项**（已确认 `create --help`），投递失败=永久丢失
- "执行 ok" ≠ "投递成功"：cron list 的 Last run ok 只代表脚本跑完，必须看 ⚠ Delivery 行

## 处置

- 补发：`hermes cron run <job_id>` 手动触发（限流窗口过后通道即恢复）
- 错峰：盘前简报 9:32 → 9:39（避开撞车点）
- **再修正（用户指出"盘前 9:32 太晚不对"）**：积存金 9:10 开盘，盘前简报必须在开盘前 → 最终改为 **8:50 周一至五**（在 7:30 隔夜扫描/8:08 日历/8:10 完整报告之后、9:05 白泽 catalyst 之前的空窗）。教训：排期先核对交易时段（民生积存金 9:10-次日2:00），"盘前"必须 < 9:10
  - 调度是服务器侧 `hermes cron create` 建的，本地仓库无源文件会回写覆盖
- 遗留：白泽高频推送是结构性压力源，是否收敛需用户决策（跨项目，未动）

## 规则

- 关键推送丢失排查顺序：通道存活(gateway双向) → 窗口限流(errors.log时间簇) → 任务投递标记(⚠) → 脚本执行(ok)
- 部署/排查涉及微信投递时，"用户实际收到"才是完成标准，脚本 ok 不算
