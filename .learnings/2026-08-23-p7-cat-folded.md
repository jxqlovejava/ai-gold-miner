# P7 cat 直出当日废除：工具输出终端折叠不可见（2026-08-23）

## 事故

8/23 上午引入 P7「cat 直出」模式（报告落盘后用 `cat` 工具输出展示全文，模型不复述，省 60-90s/轮）。
当日下午用户两次反馈：
1. 「为什么现在金价分析没有在终端输出每一块的分析？」
2. 「不对啊，cat 输出都被折叠起来了」

第一轮我还解释「这是你自己选定的提速模式、板块一块没少」——错把设计意图当实际效果。
第二轮用户点明折叠，才确认根因。

## 根因

P7 的设计前提是「cat 输出 = 完整全文到控制台」，**从未验证终端渲染行为**：
- Bash/Read 工具输出长文本在终端 UI 会被折叠收起，用户只看到几行预览
- 只有 assistant 自己的文本输出才完整渲染
- 所以 cat 直出的实际效果 = 用户只看到模型几句摘要 = 变相摘要模式，直接违背用户 8/22「REUSE 保持完整重发」的选定

省 token 的方向没错，但省错了地方：砍掉了用户唯一能看见内容的通道。

## 修复（P9 模型全文直发）

- SKIP 场景（REUSE+SKIP / RERUN+SKIP）：bundle 骨架 = 报告全文，模型直接逐字转贴输出（一遍生成，无需 Write/Read/cat），前置 2-3 行增量摘要（决策+价格校验+条件单变动+评分 delta）
- ASSEMBLE_OK 场景：Write 校验通过后模型输出同内容全文，接受两遍生成 ~10k token ≈60-90s 为可见性必要成本
- 已落地：SKILL.md 输出铁律 10 P9 条款 + 步骤进度条款 + 铁律 7 表述；memory feedback_scan_report_file.md 第 10 条改写

## 防复发

1. **任何「用工具输出替代模型文本」的展示优化，必须先验证终端实际渲染效果**（折叠/截断行为），不能只看设计意图
2. 用户可见性 > token 成本：用户已两次选定「完整重发」，此后任何摘要化/折叠化提案直接拒绝
3. 用户反馈「没输出」时先怀疑渲染通道（工具输出折叠），而不是解释设计意图
