# Learning: 不要把旧闻里的“前瞻事件”当作未来事件

Date: 2026-06-16
Trigger: 用户指出 5 月非农就业已经公布，而我之前的分析仍按“等待周五非农”给出建议。

## 学到的规则

1. **新闻里的“将/等待/预计”必须先看日期**
   - 任何带时间状语的文章，先核对 `date` 字段是否早于事件发布日
   - 6 月 1 日写“等待周五非农”的文章，到 6 月 16 日已经失效

2. **事件日期不能靠新闻推断，必须查 T0 日历**
   - 非农数据：BLS 发布日程 / CME 经济日历
   - FOMC：美联储官网 / CME FedWatch
   - CPI/PPI：BLS 日程
   - 只有 T0 日历确认后，才能写“已公布 / 未公布”

3. **Pipeline 缓存/旧数据会让错误信号长期存活**
   - 当新闻 API 全部失败时，系统只能 fallback 到缓存或旧文章
   - 旧文章没有“事件已过期”标记，需要 agent 主动做时间线校验

4. **每次时间敏感分析前做三步检查**
   - 当前日期是什么？
   - 该事件官方发布日是哪天？
   - 引用的信息源是否在发布日之前？

## 如何应用

- 跑 `gold-miner scan` 后，如果新闻信号里出现“等待 / 将公布 / 预计”，立即核对事件官方日历
- 分析前先用 BLS/CME/央行官网确认关键数据发布时间
- 在输出里明确标注“事件状态：已公布 / 待公布 / 已过期”，而不是直接复制文章措辞
- 把这条检查加入 `gold-miner doctrine --check` 或分析 pipeline 的 pre-flight checklist
